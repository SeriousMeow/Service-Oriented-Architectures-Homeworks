## Primary keys и clusetering keys

В качестве primary key используется id главной сущности в конкретной таблице (например, product_id в таблицах, ориентированных на поиск по товару). Благодаря этому поиск по этому id в cassandra быстр.

В качестве clustering key используются остальные поля (id), по которым хочется делать фильтрацию, поскольку для нормально работы фильтров cassandra важно иметь их в primary key или clustering key (только со сканированием).

## Гарантия чтения Cassandra

Я выбрал гарантию ONE, поскольку это обеспечит более быстрое чтение. Это уменьшает задержку между чтением и записью, что уменьшает вероятность устаревания данных в промежутке между ними.

## V2 схема

В Schema Registry используется совместимость BACKWARD (значение по умолчанию). Это вполне нормально, поскольку не ожидается большой задержки между поставщиком и потребителем данных kafka (одно изменение схемы займет значительно больше времени, поэтому не будет расхожений больше чем на одну версию).

Для добавления новой версии события:
1. Сделать новую схему, совместимую с предыдущей по BACKWARD
2. Поддержать новую схему в consumer
3. Обновить схему в producer. Он автоматически зарегистрирует новую версию в Schema Registry, если это не было сделано ранее.
